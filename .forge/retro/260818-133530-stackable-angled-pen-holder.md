# 2026-08-18 — 적층형 경사 필통 FreeCAD 파라메트릭 모델

## 계획 대비 실제
- 계획대로 된 것: 부품 3종을 파라메트릭 스크립트 하나로 생성하고 헤드리스 검증까지 통과. 외형 치수·경사각·나사 규격·스냅 공차 모두 합의값과 일치. 모든 치수가 스크립트 상단 상수로 노출되어, 이후 폭 80→70mm·칸 수 변형·마감 모듈 추가가 전부 파라미터/함수 인자 수정만으로 처리됨.
- 어긋난 것: 5개 조각 중 4개가 FreeCAD/OCC의 API 함정으로 우회 설계를 요구했다(아래 학습). 형상 목표 자체는 어긋나지 않았고, 전부 구현 수단의 문제였다. 계획에 없던 판단 3건: 전 칸 앞턱 통일, 상단 라운드 생략, 스냅 돌기를 발자국 안쪽으로.

## 학습
- 다음에 다르게 할 것:
  1. **헬리컬(나사산) 솔리드에는 OCC 정리 연산을 걸지 말 것.** `removeSplitter()`는 유효한 솔리드를 invalid로 만들고, `common()` 클리핑은 *조용히 실패*해 잘리지 않은 형상을 반환한다. 나사산 끝단은 잘라내지 말고 다른 재료 속에 묻히도록 배치하는 편이 안전하다.
  2. **치수 검증에 `Shape.BoundBox`를 쓰지 말 것.** 트림 전 곡면 제어점 기준이라 헬리컬 절삭 후 실제보다 2.6mm 크게 나온다. `tessellate()` 기반 실측 bbox를 쓸 것.
  3. **STL은 `MeshPart.meshFromShape` + `mesh.write()`로 내보낼 것.** `Shape.exportStl()`은 ASCII를 써서 헬리컬 부품이 8.6MB → 138KB 차이가 난다.
  4. **기능이 성립하는지를 검증 항목으로 만들 것.** 이 작업의 검증 9항목은 "유효 솔리드·치수 일치"만 봤고, 그래서 *나사가 아래턱 위로 10mm만 올라와 두께 30mm 미만 상판에는 닿지 않는다*는 결함을 놓쳤다(사용자가 실제 출력 후 발견). 이후 '체결 가능 상판 두께'·'구멍 주변 재료'·'앞턱 자기지지 각도'처럼 **기능 성립 조건을 계산해 판정하는 항목**을 넣자 같은 종류의 결함이 즉시 걸렸다. 치수 검증은 "그린 대로 그려졌나"만 답하고 "쓸 수 있나"는 답하지 않는다.
  5. **출력 방향을 설계 초기에 정하고 그 방향 기준으로 형상을 판단할 것.** 서포트 면적을 광선 투사로 실측해 보니 방향에 따라 3,700 vs 28,800mm²로 8배 차이였고, 앞턱의 수직 단차 같은 결함은 "뒷면을 베드에"라는 전제를 세운 뒤에야 보였다.
- 문서 신선도: 퀵 레인(fg-quick) 작업이 연달아 형상을 바꾸면서 CONTEXT.md 용어 정의가 실제와 어긋났다(칸 수·부품 구성). 퀵 레인은 설계상 문서를 갱신하지 않으므로, 퀵 작업이 여러 건 누적되면 회고 때 용어집을 한 번 대조하는 편이 좋다.
