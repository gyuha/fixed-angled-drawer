# 4개 변형(폭 × 두께)을 폴더별로 생성

## 목표 / 비목표
- 목표: 루트에서 `pen_holder.py`를 **한 번 실행**하면 폭 70/80mm × 두께 세트 2종(얇은판/두꺼운판)의 **4가지 변형**이 각자의 폴더에 생성된다. 각 변형은 기존 검증 32항목을 모두 통과한다.
- 비목표: 부품 형상·인터페이스 변경, 변형 개수 확장 구조(4종 고정으로 충분), 변형별 렌더 생성(기준 1종만), 변형 간 자동 비교 리포트, 릴리스 자산 재업로드.

## 확정 사양 (그릴링 합의)
- **폴더 구조**: `output/` 아래 **한 단계 평면**. 폴더명에 폭과 벽 두께가 모두 들어가 파일이 밖으로 나가도 출처가 분명하도록 한다.
  ```
  output/
    w70-wall2.4/   ← 기준 변형 (현재 output/ 내용에 대응)
    w70-wall3.0/
    w80-wall2.4/
    w80-wall3.0/   ← 옛 output-8cm/ 에 대응
  ```
- **변형 정의** (두께는 세트로 움직인다):
  | 폴더 | `W` | `WALL` | `BOT_T` | `SHELF_T` |
  |------|-----|--------|---------|-----------|
  | `w70-wall2.4` | 70 | 2.4 | 3.0 | 3.0 |
  | `w80-wall2.4` | 80 | 2.4 | 3.0 | 3.0 |
  | `w70-wall3.0` | 70 | 3.0 | 4.0 | 4.0 |
  | `w80-wall3.0` | 80 | 3.0 | 4.0 | 4.0 |
  `wall3.0`은 **예전 두께 전체 복원**이다(선반·바닥 4.0 포함). 적층 호환을 결정하는 것은 벽 두께뿐이므로 폴더명에는 벽 두께만 넣는다.
- **구현 제약(그릴링 중 확인)**: `WALL`에서 파생되는 모듈 상수는 `IN_D = D - WALL` **하나뿐**이고 `W`·`BOT_T`·`SHELF_T`에서 파생되는 것은 없다. 따라서 변형 전환은 `W`·`WALL`·`BOT_T`·`SHELF_T`·`IN_D` 다섯 개만 다시 세팅하면 된다 — 파생 상수를 놓쳐 조용히 틀린 형상이 나오는 것을 막기 위해 **변형마다 `IN_D == D - WALL` 검증**을 넣는다.
- **기존 파일 이관**: `output-8cm/`은 폐지하고 그 자리는 `w80-wall3.0/`으로 새로 생성한다(현재의 모든 기능이 들어간 형상). 직접 만드신 슬라이서 프로젝트 2개는 **삭제하지 않고** 대응 폴더로 옮긴다 — `output/fixed-drawer.3mf` → `w70-wall2.4/`, `output-8cm/fixed-drawer.3mf` → `w80-wall3.0/`.
- **렌더**: 기준 변형(`w70-wall2.4`) 5장만 유지하고 **위치는 `output/` 루트 그대로** 둔다(README 링크 유지, 벽 2.4/3.0은 렌더에서 구분되지 않아 중복). `screenshot.py`가 읽는 FCStd 경로는 기준 변형 폴더로 바꾼다.
