# 실행 기록 — 출력 시간·필라멘트 절감

## 조각별 결과
- S1 모델 파라미터 축소(벽 2.4 / 선반·바닥 3.0) + 스냅 물림 가드 검증 추가 — ✅ 계획대로
- S2 출력 시간·필라멘트 실측 — ⚠ **미달**: BambuStudio CLI가 실행 중인 GUI에 막혀 슬라이싱 불가. 계획의 대안 조항(추정치로 대체하지 않고 사실·절차 기록)으로 처리
- S3 README 출력 최적화 절 + 비호환 경고 + 치수·검증 수치 정정 — ✅ 계획대로

## 계획대로 된 것
- `WALL` 3.0→2.4, `BOT_T`·`SHELF_T` 4.0→3.0. 검증 **32항목 전부 PASS** — 필렛 r1.4, 앞턱 램프 53.5°, 스냅 물림 1.55mm, 서랍·레일 공차가 모두 유지됨.
- 재료 실측(실사용 5부품 세트): **601 → 511cm³ (745g → 634g, −15%)**. 8부품 전량은 1,066 → 894cm³.
- 신규 검증 항목 `snap wall guard` 추가 — 벽을 더 얇게 하면 스냅 돌기가 벽을 관통하거나 물림이 사라지는 관계를 계산으로 고정(현재 관통 여유 0.85mm).
- README: 출력 최적화 절(부품 선택 −43% 실측표·서포트 OFF·레이어 0.28·wall_loops 3·시간 측정 명령), 버전 간 비호환 경고, 치수·파라미터·검증 수치 정정.

## 현장 결정 (계획에 없던 판단)
- **사용자 질문으로 우선순위를 재검토했다.** "모델 수정이 꼭 필요한가"라는 지적을 받아 레버를 분해해 보니, 모델 수정(−15%)은 네 레버 중 가장 작고 유일하게 대가(강성 −20%, 기존 3.0mm판과 비호환)를 치르는 레버였다. 범위 조정(−43%)과 레이어 높이가 더 크고 대가가 없다. 사용자가 "이미 바꿨으면 유지"로 확인해 유지했으나, 이 우선순위는 문서에 반영했다(README에서 부품 선택을 1번, 벽 두께는 파라미터 표로만).
- 타공 확대는 그릴링 단계의 실측(−1%)대로 기각 유지.
- 시간 절감은 README에서 **수치 없이 방향만** 기술하고 "이 프로젝트에서 실측하지 못했음"을 명시했다. 통설(25~30%)을 측정치처럼 쓰지 않았다.

## 막혔던 곳 / 학습
1. **BambuStudio CLI는 GUI가 실행 중이면 동작하지 않는다.** `Initializing StaticPrintConfigs`에서 멈춘 뒤 타임아웃(종료코드 124). `--datadir`로 설정 디렉터리를 분리해도 우회되지 않았다. 사용자가 다른 프로젝트를 열어 작업 중이었으므로 앱을 강제 종료하지 않았다 — 측정보다 사용자의 작업 보존이 우선이다.
2. **CLI에 사용자 프로파일을 그대로 먹일 수 없다.** 3mf의 `Metadata/project_settings.config`는 병합된 프로젝트 설정이라 `--load-settings`가 `from project unsupported`로 거부한다. 내장 프리셋(machine/process/filament json)을 각각 지정해야 하며, 그러면 절대 시간이 사용자 환경과 달라진다.
3. GUI가 열리기 전 성공한 1건: 신규(2.4mm) `topmodule` = **7시간 2분 / 필라멘트 17.55m** (CLI 기본 프로파일, 레이어 0.2·벽 2줄·인필 20%·서포트 없음). 단일 표본이고 사용자 프로파일(외벽 200~350mm/s)과 다르므로 30시간과 직접 비교할 수 없다.
